# Multi-language (vi / en) — Design

Date: 2026-10-12
Branch: `feat/i18n` (worktree `.claude/worktrees/i18n`, based on `origin/main` 00d67c1)

## Goal

Every UI string in Quick Split can be shown in Vietnamese or English. Vietnamese
stays the default. A visitor's first visit follows the browser language; a
VI | EN switcher overrides it and is remembered. URLs do not change, so group
links already shared keep working.

## Decisions

- Locales: `vi` (default), `en`. No URL prefix, no `[lang]` segment, no proxy.
- Locale source, in order: `locale` cookie → `Accept-Language` header → `vi`.
- No new dependency. Hand-rolled typed dictionaries.
- Money stays VND in both locales (the app and VietQR are Vietnam-only); only
  grouping changes: vi `150.000đ`, en `150,000₫`.
- Dates stay in `Asia/Ho_Chi_Minh`; vi `12/10/2026`, en `12 Oct 2026` (`en-GB`, `dateStyle: 'medium'`).
- User data is never translated: group names, member names, expense titles.
  Settle-up payments keep their stored title `'Thanh toán'`; the list shows the
  localized label for payments instead of the raw title.

## Architecture

### `lib/i18n/`

- `vi.ts` — `export const vi = { ... }`, nested by area (`common`, `home`,
  `group`, `expense`, `balances`, `members`, `errors`, `meta`). Strings with
  values are functions, e.g. `paidBy: (name: string) => \`${name} trả\``.
- `en.ts` — `export const en: Dict = { ... }`. Typing against `Dict` makes a
  missing or misspelled key a `tsc` error.
- `index.ts` — `type Dict = typeof vi`, `type Locale = 'vi' | 'en'`,
  `LOCALES`, `DEFAULT_LOCALE = 'vi'`, `dicts: Record<Locale, Dict>`,
  `pickLocale(cookie: string | undefined, acceptLanguage: string | null): Locale`.
  `pickLocale` returns the cookie if it is a supported locale; otherwise parses
  `Accept-Language` (tags with `q` weights, highest first, primary subtag
  matched: `en-US` → `en`); otherwise `vi`. Pure, no Next imports, safe for
  client bundles.
- `server.ts` — `getLocale()` (React `cache`d; reads `cookies()` + `headers()`
  from `next/headers`) and `getT()` → `dicts[await getLocale()]`. Server-only.

### Client side: `app/locale-provider.tsx`

`'use client'` context: `LocaleProvider({ locale, children })`, and hooks
`useLocale()` and `useT()` (→ `dicts[locale]`). Only the locale string crosses
the server/client boundary; dictionaries are imported in the client bundle
(both together are a few KB). Client components that need text call `useT()`:
`create-group-form`, `error`, `copy-link`, `delete-button`, `expense-form`.
`member-name-form` and `submit-button` already receive text via props and do not change.

### Root layout (`app/layout.tsx`)

- `const locale = await getLocale()` → `<html lang={locale}>`, wraps children in
  `<LocaleProvider locale={locale}>`.
- `generateMetadata()` replaces the static `metadata`, description from `t.meta`.
- Renders the switcher above `{children}`: a `<form action={setLocale}>` with
  two submit buttons `name="locale" value="vi|en"`, current one bold. Works without client JS.
- Reading cookies in the root layout under `cacheComponents` requires
  `export const instant = false` on the layout (same opt-out the group pages
  already use). Verify with `npm run build`.

### Server action `setLocale(formData)` (`app/actions.ts`)

Validates `locale` against `LOCALES` (ignore anything else), sets cookie
`locale` (`path=/`, `maxAge` 1 year, `sameSite=lax`). Setting a cookie in a
server action re-renders the current route, so the page switches immediately.

### Validation (`lib/validation.ts`)

- Schema messages become keys of `Dict['errors']` (e.g. `'memberNameRequired'`).
- The exact-sum issue carries values: `ctx.addIssue({ code: 'custom', message: 'exactMismatch', params: { total, amount } })`.
- `firstError(e: ZodError, t: Dict): string` → looks up `t.errors[issue.message]`;
  functions are called with `params`. Any message that is not a known key (zod
  built-ins, e.g. `Infinity`, wrong type — only reachable with tampered input)
  maps to `t.errors.invalid`.
- `z.config(z.locales.vi())` is removed: zod config is process-global, so
  switching it per request would race between concurrent requests.
- Server actions call `const t = await getT()` and pass `t` to `firstError`;
  their inline messages (`'Tên thành viên bị trùng'`, `'Không tìm thấy khoản chi'`, …) become `t.errors.*`.

### Formatting (`lib/money.ts`, `lib/date.ts`)

- `formatVnd(n, locale: Locale = 'vi')`: vi `Intl.NumberFormat('vi-VN')` + `đ`;
  en `Intl.NumberFormat('en-US')` + `₫`.
- `formatDateVn` → `formatDate(d, locale: Locale = 'vi')`, same timezone.
- Defaults keep current call sites and tests valid; every UI call site passes the locale.

### Payment label (`lib/split.ts`)

Add `PAYMENT_TITLE = 'Thanh toán'` and `isPayment(e)` (title equals
`PAYMENT_TITLE`, `splitType === 'exact'`, one split). `recordPayment` uses the
constant. The expenses list shows `t.expense.payment` for payment rows.

## String inventory (origin/main)

About 60 strings in: `layout`, `page` (home), `create-group-form`, `error`,
`g/[id]/page` (tabs, members, chips, expenses, balances), `copy-link`,
`delete-button`, `not-found`, `expense/new`, `expense/[eid]`, `expense-form`,
`actions`, `validation`. Placeholders are localized too (vi `Đà Lạt 2026` /
`An\nBình\nChi` / `Ăn tối`; en `Weekend trip` / `Alice\nBob\nCharlie` / `Dinner`).
The plan lists every key.

## Error handling

- Unknown/garbage cookie value → ignored, falls back to header/default.
- `setLocale` with an unsupported value → no-op.
- Missing translation → impossible at runtime (`tsc` fails on a missing key).

## Testing

- `lib/i18n/index.test.ts`: `pickLocale` — cookie wins; invalid cookie ignored;
  `en-US,en;q=0.9` → `en`; `fr,vi;q=0.5` → `vi`; `fr` → `vi`; `null` → `vi`;
  q-order respected (`vi;q=0.4,en;q=0.8` → `en`).
- `lib/validation.test.ts`: existing cases call `firstError(e, vi)` and keep
  their Vietnamese expectations; add en assertions for a plain key, an
  interpolated one (`exactMismatch`) and the `Infinity` fallback (`t.errors.invalid`).
- `lib/money.test.ts`, `lib/date.test.ts`: add one en case each.
- `npm run lint && npm run build` pass; build confirms the layout cookie read.
- Browser: first visit with an English browser shows English; switch to VI and
  back, reload keeps choice; create group, add expense with a wrong exact sum
  (localized error), record payment (shows localized payment label), 404 page,
  in both languages; `<html lang>` follows the choice.

## Out of scope

- More than two locales, URL-based locales, SEO alternates.
- Translating user-entered data or the stored payment title.
- Per-user stored preference beyond the cookie.
